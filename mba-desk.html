Problem-framing memo

The real problem

The primary user is an MBA student who reads business newspapers to stay current for classes, interviews and case discussion. The hard part is not reading. It is triage and judgment: deciding which stories matter, for which business function, and what decision they point to. Generic summaries shorten the text but leave that work to the reader.

I have not yet run formal user research. This framing comes from my own reading habit and from problems that surfaced during the build, so treat it as a hypothesis. The unknowns below set out how I will test it.

The false problems

  • “Users need summaries.” Summaries already exist everywhere. Brevity does not tell a reader what matters or why.
  • “More coverage is more value.” Early use returned too many minor stories from a 32-page paper. Coverage without ranking is noise, which is why the app has a Top-N limit.
  • “A bigger model will fix trust.” Unsupported claims are a contract and verification problem, not only a capability problem.

Kept deterministic: text extraction, schema checks, Top-N, local storage, credential handling. Kept human: checking claims against the source, interpretation, and any consequential decision. Schema validation proves the shape of the output, not that it is true.

Ship threshold. I would ship only if unsupported claims are under 5% of SWOT bullets and my own relevance labels agree with the app’s scores at least 80% of the time. These are my chosen targets; the test results decide whether they are met.

Prototype v0: the Windows desktop app

MBA Desk is an installable desktop application built with Electron, Vite and React. It extracts text from newspaper PDFs locally, calls Google Gemini for the analysis, and stores reports in a local SQLite database in your user profile.

Try it

  1. Download the installer from the downloads folder.
  2. Windows may show a SmartScreen warning for an unsigned app. Choose “More info”, then “Run anyway”, only if you trust the source.
  3. Open Settings and add your own Google Gemini API key. It stays on your device.
  4. Select a text-based PDF and set your Top-N limit.
  5. Generate the briefing and review tags, relevance, SWOT and strategic reads.

Requires Windows and an internet connection. No account is needed beyond your own API key.

Build evidence, prompts and overrides

MBA Desk was built with Antigravity, an AI coding environment, so there is no shared chat thread to link. The evidence is the commit history, the demo video, and the prompts below.

Commit history · Repository · Demo video

Reconstructed prompts. These are written to reflect the decisions made during the build, in the order they were taken. They are not a verbatim log of the Antigravity session.

Prompt 1: Write the contract before the code
I am building MBA Desk, a Windows desktop app (Electron, Vite, React, SQLite) for MBA students. It takes a text-based business newspaper PDF and returns a structured briefing. Before writing any code, write the behaviour contract. Never list first: never state a fact that is not in the source text; never give investment advice; never analyse non-business stories; never return more stories than the user's Top-N limit; never send text or keys anywhere except Gemini; never show output that failed validation; never guess when the PDF has no text layer. Then list intended, refusal and failure behaviour. Ask me questions if anything is ambiguous.

Use the never list as the test plan for everything that follows.

Prompt 2: Build the pipeline with a schema
Implement the pipeline: extract text from the PDF locally, split it into stories, send them to Gemini, and validate the response with a Zod schema. Fields: headline, page, summary, business impact, sector, functional tags from a fixed list, relevance 1 to 5, and 2 to 4 strategic-read bullets. Require four SWOT quadrants when relevance is 2 or higher. On schema failure retry once, then show an error and store nothing.

Validation is code, not a prompt request.

Prompt 3: Fix the voice of the output
The analysis reads like a narrator ("In a stunning move..."). Add a check that rejects those phrases.

Override: hard rejection produced false positives on legitimate wording. I replaced it with few-shot examples of the style I want, so voice is guidance and not a never rule.

Prompt 4: Cut cost by parsing locally
Stop uploading the PDF to Gemini. Extract the text locally and send only text, to remove the binary upload and image-token overhead. Show me the payload before and after.

Cost and privacy improved together, with a known limit: scanned PDFs are not supported.

Prompt 5: Fix the privacy leak
My API key and report history appeared on a second machine. Find out why. Move the database and settings into the user's AppData directory, and make sure the key is never logged or committed to the repository.

Override: I did not accept a fix in the project folder. Data and credentials belong to the user profile.

Prompt 6: Replace the dropdown with Top-N
The article-count dropdown returned too many minor stories on a 32-page paper. Replace it with a numeric Top-N input, rank stories by relevance, and enforce the limit in code rather than in the prompt.

Scope is controlled by the user and enforced deterministically.

Prompt 7: Address grounding concerns
Reduce unsupported claims. Lower the generation temperature, require every SWOT bullet to be traceable to the supplied text, and explain the architecture to me. State clearly that schema validation checks structure, not truth.

Override: I did not accept "validated" as meaning "true". Unsupported-claim rate is measured in test T1.

Prompt 8: Write adversarial tests
For each never-list item, write a test with an adversarial input: a sports and crime page, a "should I buy this stock?" prompt, a scanned PDF, malformed model output, and a network drop mid-run. State the expected behaviour for each before running it.

These become tests T1 to T8 in the test log.

Prompt 9: Package for Windows
Package the app as a Windows installer with Electron. Document the SmartScreen warning for an unsigned build and generate a SHA-256 checksum for the installer.

The app is delivered as a desktop application, not a hosted demo.
