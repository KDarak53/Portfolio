Problem-framing memo

The real problem

The primary user is an MBA student who reads business newspapers to stay current for classes, interviews and case discussion. The hard part is not reading. It is triage and judgment: deciding which stories matter, for which business function, and what decision they point to. Generic summaries shorten the text but leave that work to the reader.

I have not yet run formal user research. This framing comes from my own reading habit and from problems that surfaced during the build, so treat it as a hypothesis. The unknowns below set out how I will test it.

The false problems

  • “Users need summaries.” Summaries already exist everywhere. Brevity does not tell a reader what matters or why.
  • “More coverage is more value.” Early use returned too many minor stories from a 32-page paper. Coverage without ranking is noise, which is why the app has a Top-N limit.
  • “A bigger model will fix trust.” Unsupported claims are a contract and verification problem, not only a capability problem.

Kept deterministic: text extraction, schema checks, Top-N, local storage, credential handling. Kept human: checking claims against the source, interpretation, and any consequential decision. Schema validation proves the shape of the output, not that it is true.

Ship threshold. I would ship only if unsupported claims are under 5% of SWOT bullets and my own relevance labels agree with the app’s scores at least 80% of the time. These are my chosen targets; the test results decide whether they are met.

Prototype v0: the Windows desktop app

MBA Desk is an installable desktop application built with Electron, Vite and React. It extracts text from newspaper PDFs locally, calls Google Gemini for the analysis, and stores reports in a local SQLite database in your user profile.

Try it

  1. Download the installer from the downloads folder.
  2. Windows may show a SmartScreen warning for an unsigned app. Choose “More info”, then “Run anyway”, only if you trust the source.
  3. Open Settings and add your own Google Gemini API key. It stays on your device.
  4. Select a text-based PDF and set your Top-N limit.
  5. Generate the briefing and review tags, relevance, SWOT and strategic reads.

Requires Windows and an internet connection. No account is needed beyond your own API key.
